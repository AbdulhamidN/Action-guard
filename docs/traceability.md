# ActionGuard — Requirements Traceability Matrix

## 1. Overview & Traceability Methodology

This document provides a comprehensive traceability matrix linking every functional requirement (FR) and non-functional requirement (NFR) from `docs/requirements.md` (the Requirements Analysis) to its delivering module in `docs/development-plan.md`, current implementation status, and verifying automated test evidence under `tests/`.

### Status Definitions:
- **Done**: Fully implemented and validated by at least one named automated test that directly proves the required behavior.
- **Partial**: Partially implemented in the current codebase, or lacking dedicated test coverage, or delivered across multiple roadmap modules where later modules remain unstarted.
- **Not started**: Planned in the development roadmap (Modules 8–13) but not yet implemented.
- **No module owns it**: Not assigned to any delivery module in the development plan (Modules 1–13); flagged as future research or non-MVP architectural expansion.

### Explicit Deferrals & Cross-Module Alignments:
1. **Frontend Dashboard Real-Time Hook**: The Module 7 task bullet *"Connect the frontend to the real-time event stream"* and the acceptance check *"dashboard updates live without refresh"* are explicitly deferred to **Module 12 (Dashboard and Explainability)**, when the React frontend application is constructed.
2. **REST vs. WebSocket Payload Alignment**: Completed in Module 12a. REST endpoints (`GET /api/v1/sessions/:id` and `POST /api/v1/risk/evaluate`) are now strictly aligned with WebSocket user rooms: returning tier-only risk evaluations (`risk_tier`, `evaluated_at`, `explanation.user_facing`) without numeric scores, signal weights, or admin explanations. Full technical detail is restricted to authenticated admin endpoints (`/api/v1/admin/*`).

### Current Code Audit (Session Controls & Privilege):
- **Idle Timeout (FR-23)**: `src/services/sessionService.js` and `src/storage/redis.js` implement atomic Lua sliding renewal (`validateAndTouchSession`), bounded write-throttling (`RENEWAL_THROTTLE_SECONDS = 30`), passive WebSocket revalidation (`touch: false`), and fail-safe idle timeout enforcement. Delivered by **Module 10a**. Status: **Done**.
- **Maximum Session Age (FR-25)**: `src/services/sessionService.js` stores immutable absolute caps (`max_expires_at`) in MySQL and Redis, aligns JWT expiration with maximum lifetime (`MAX_SESSION_LIFETIME_SECONDS`), clamps sliding renewals to remaining maximum lifetime, and terminates immediately upon reaching cap. Delivered by **Module 10a**. Status: **Done**.
- **Short-Lived Elevated Trust & Local Step-Up Verification (FR-8, FR-9, FR-24, FR-27)**: `src/services/elevationService.js`, `src/services/stepUpService.js`, and `src/routes/sessions.js` implement local one-time challenge generation (`POST /api/v1/sessions/:id/step-up/challenge`), constant-time SHA-256 verification and ES256 ticket issuance (`POST /api/v1/sessions/:id/step-up/verify`), external ticket consumption (`POST /api/v1/sessions/:id/elevate`), allowlisted scope isolation, automatic TTL expiration reverting to baseline trust, risk-tier ceiling revocation when session risk escalates above `granted_at_risk_tier`, deterministic Set-indexed cascade revocation on logout/containment, and bulk device revocation on password change. Delivered by **Modules 10a & 10b**. Status: **Done**.
- **Policy Enforcement Point, Protective Containment & Decision Audit (FR-3, FR-4, FR-5, FR-6, FR-7, FR-28, FR-30, FR-37, NFR-3, NFR-4, NFR-12)**: `src/middleware/pep.js`, `src/services/containmentService.js`, and `src/routes/accountActions.js` implement pre-execution PEP authorization across all five sensitive account routes (`/api/v1/account/*`), server-side context extraction (`src/utils/requestContext.js`), mandatory synchronous `policy_decisions` persistence stamped with `policy_id` and `policy_version`, `recommend_only` non-blocking advisory enforcement, fail-closed `503 policy_enforcement_unavailable` behavior, critical-risk session invalidation + 15-minute dual-store protective account lock (`account_lock:<userId>` + `users.locked_until`), and tier-only vs. admin `decision:recorded` Socket.IO broadcasts. Delivered by **Module 10b**. Status: **Done**.
- **Cooling-Off Enforcement (FR-32)**: `src/services/coolingOffService.js`, `src/jobs/coolingOffWorker.js`, `src/routes/coolingOff.js`, and `src/database/models/DelayedAction.js` implement pluggable PEP `setDelayHandler` integration, dual MySQL + Redis delayed action persistence with credential sanitization, cryptographic single-use cancellation tokens (`ctkn_*`) verified in constant time, deadline enforcement (`action_still_cooling_off`), atomic concurrency-safe state transitions, Zero Trust pre-execution rechecks (user lock, session validity, risk escalation, and policy recheck), and distributed background worker processing. Delivered by **Module 10c**. Status: **Done**.
- **Security Fixes & Hardening (Module 11c / F1-F5)**: Startup secrets validation (`assertRequiredSecrets`), post-password login hold timing and recognized device bypass (`POST /api/v1/auth/login`), atomic multi-dimensional step-up challenge limits via Redis Lua (`-- ATOMIC_CHECK_STEP_UP_CHALLENGE_LIMITS`), constant-time service API key comparison via SHA-256 digests (`authenticateApiKey`), and fail-safe PEP enforcement under `recommend_only` mode (`src/middleware/pep.js`). Delivered by **Module 11c**. Status: **Done**. Evidence: `tests/module11c-security-fixes.test.js` (23 tests: F1-01..F1-05, F2-01..F2-05, F3-01..F3-08, F4-01..F4-04, F5-01).
- **Dashboard API, Admin Session Token & REST Alignment (FR-29, FR-33, FR-34, NFR-2, NFR-16)**: `src/services/adminTokenService.js`, `src/middleware/auth.js` (`requireAdminToken`), `src/routes/admin.js`, `src/routes/me.js`, `src/realtime/payloads.js`, and `src/database/migrations/011_dashboard_overview_indexes.js` implement short-lived opaque admin session tokens (`agadm_*`), REST/socket payload alignment (tier-only responses on `GET /api/v1/sessions/:id` and `POST /api/v1/risk/evaluate`), user read endpoints (`/api/v1/me/sessions`, `/events`, `/risk-history`, `/decisions`), and admin telemetry endpoints (`/api/v1/admin/overview`, `/users`, `/users/:id/*`, `/policy`). Delivered by **Module 12a**. Status: **Done**. Evidence: `tests/dashboard-api-admin-token.test.js` (30 tests: A1-A7, B1-B8, C1-C10, D1-D5).
