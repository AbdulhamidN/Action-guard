# ActionGuard Frontend Shell

Frontend foundation and real-time app shell for ActionGuard, built with React 18, Vite, Tailwind CSS, React Router, TanStack React Query, and Socket.IO client. Plain JavaScript with JSDoc typing.

## Development

### 1. Running the Development Server

From the repository root:

```bash
npm run dev:frontend
```

Or from within the `frontend/` directory:

```bash
cd frontend
npm run dev
```

The Vite dev server runs at:
```text
http://localhost:5173
```

### 2. Development Proxy (No CORS)

Vite is configured in `vite.config.js` to proxy all backend requests directly to the ActionGuard Express server:

- `/api` → `http://localhost:3000/api`
- `/socket.io` → `http://localhost:3000/socket.io` (with WebSocket upgrade `ws: true`)

Because all requests are proxied through Vite's local dev server, no CORS middleware is required or enabled on the backend.

### 3. DEV-Only Fingerprint Override

In development builds (`import.meta.env.DEV`), the device fingerprint service (`src/services/fingerprint.js`) checks `localStorage.getItem('ag_fp_override')`. If set to a valid non-empty string ($\ge 4$ characters), this value replaces the hardware fingerprint generated by FingerprintJS.

This allows developers to open multiple browser profiles or incognito tabs to simulate distinct devices (e.g. testing new device detection and account lock containment):

```javascript
// In browser DevTools console (DEV mode only):
localStorage.setItem('ag_fp_override', 'fp_simulated_laptop_01');
```

To revert to the hardware fingerprint, simply remove the key:

```javascript
localStorage.removeItem('ag_fp_override');
```

**Security invariant:** In production builds (`npm run build`), the override branch is guarded by `if (import.meta.env.DEV)` and is statically stripped out by the bundler compiler (tree-shaken). It cannot be invoked in production.

## Production Build & Static Serving

### 1. Building the Frontend

```bash
npm run build:frontend
```

This compiles the SPA into `frontend/dist`.

### 2. Serving via Express (`SERVE_FRONTEND=true`)

When `SERVE_FRONTEND=true` is set in the environment, the ActionGuard Express server (`src/app.js`) serves the built SPA:

```bash
SERVE_FRONTEND=true npm start
```

- Static assets in `frontend/dist` are served directly.
- Non-API GET requests that do not target `/api`, `/socket.io`, or `/health` fall back to `frontend/dist/index.html` for client-side React Router navigation.
- Unmatched `/api/*` endpoints continue to return JSON 404 `{ error: { code: "not_found", message: "Not found", status: 404 } }`.
- Helmet Content Security Policy (CSP) is dynamically configured when `SERVE_FRONTEND=true` to permit `'self'` scripts, styles, fonts, images, and WebSocket connections without weakening security boundaries.

## Architecture & Authentication Boundaries

The frontend separates user and admin operations into distinct isolated shells:

1. **User Portal (`/app/*`)**:
   - Authenticates via `POST /api/v1/auth/login` with `x-device-fingerprint`.
   - Stores the issued JWT strictly in `sessionStorage` (`ag_user_token`).
   - Sockets connect with `auth: { token }` and receive account-scoped telemetry.
   - Guarded by `UserGuard`; redirects to `/login` if unauthenticated.

2. **Operator Console (`/admin/*`)**:
   - Authenticates via `POST /api/v1/admin/auth/login` with the admin API key.
   - The key is typed once, sent once, and immediately discarded (input is cleared, key is never logged or stored).
   - The issued operator token (`agadm_...`) is held strictly in JavaScript memory (`authStorage.js`). A page refresh automatically resets memory and returns to the admin login.
   - Sockets connect with `auth: { adminToken }` and receive global platform telemetry.
   - Guarded by `AdminGuard`; redirects to `/admin/login` if unauthenticated.

3. **Zero Trust Hygiene**:
   - No tokens are stored in `localStorage`.
   - Credentials are never passed in URL query parameters.
   - Server strings are rendered exclusively as plain text; `dangerouslySetInnerHTML` is prohibited.
